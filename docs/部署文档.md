# MailPost 部署文档（AWS Linux · 端口 5006）

目标：把本机 MailPost 部署到 AWS Linux（建议 Amazon Linux 2023），对外监听 **5006**，用已配置的 Gmail SMTP 发信。

本应用 **没有登录页**。谁能打开 `http://服务器:5006`，谁就能用里面的 Gmail 发信。安全组务必只放行你的办公网 IP。

---

## 一、AWS 控制台准备

### 1. 开一台 EC2

- 系统：**Amazon Linux 2023**（Ubuntu 22.04 也可，命令见文末差异）
- 架构：x86_64 或 ARM 均可
- 规格：t3.small 或以上（Next 构建需要内存，1GB 容易 OOM，建议 2GB）
- 磁盘：20GB 足够
- 密钥对：下载 `.pem`，本机保存好

### 2. 安全组（Security Group）

入站：

| 类型 | 端口 | 来源 | 说明 |
| --- | --- | --- | --- |
| SSH | 22 | 你的公网 IP | 登录服务器 |
| 自定义 TCP | **5006** | 你的公网 IP | 打开 MailPost，不要 `0.0.0.0/0` |

出站：保持默认「全部放行」。发信必须能访问：

- `smtp.gmail.com:587`（Gmail SMTP）
- `443`（npm、系统更新）

AWS 默认会限制 **25** 端口，本系统用的是 **587**，一般可通。若服务器上 `nc smtp.gmail.com 587` 不通，到 AWS 工单申请解除邮件发送限制，或检查 VPC 出站规则。

### 3. 弹性 IP（建议）

给实例绑 Elastic IP，重启后地址不变。下文用 `SERVER_IP` 表示这个地址。

## 二、本机打包上传

数据文件 `data/mailpost.json` 含 Gmail 应用专用密码，**不要提交 Git 公开仓库**。部署时单独拷到服务器。

在 Windows PowerShell（项目在 `d:\mailpost`，密钥在 `C:\keys\mailpost.pem`）示例：

```powershell
# 密钥权限（OpenSSH 要求）
icacls C:\keys\mailpost.pem /inheritance:r
icacls C:\keys\mailpost.pem /grant:r "$env:USERNAME:(R)"

# 先登录试一下
ssh -i C:\keys\mailpost.pem ec2-user@SERVER_IP
```

服务器上建目录：

```bash
sudo mkdir -p /opt/mailpost
sudo chown ec2-user:ec2-user /opt/mailpost
```

本机再上传代码（排除 node_modules、.next、.git）：

```powershell
cd d:\mailpost
scp -i C:\keys\mailpost.pem -r `
  package.json package-lock.json next.config.ts tsconfig.json `
  src public docs `
  ec2-user@SERVER_IP:/opt/mailpost/
```

`src` 目录要用递归拷完整：

```powershell
scp -i C:\keys\mailpost.pem -r src ec2-user@SERVER_IP:/opt/mailpost/
scp -i C:\keys\mailpost.pem package.json package-lock.json next.config.ts tsconfig.json ec2-user@SERVER_IP:/opt/mailpost/
```

如果本机已有可用的 `data\mailpost.json`（已接入 Gmail），再单独传：

```powershell
ssh -i C:\keys\mailpost.pem ec2-user@SERVER_IP "mkdir -p /opt/mailpost/data"
scp -i C:\keys\mailpost.pem d:\mailpost\data\mailpost.json ec2-user@SERVER_IP:/opt/mailpost/data/
```

也可用 Git：服务器 `git clone` 你的私有仓库，**仍然要单独上传** `mailpost.json`，因为该文件被 `.gitignore` 忽略。

## 三、服务器安装 Node 并构建

SSH 登录后执行（Amazon Linux 2023）：

```bash
sudo dnf update -y
sudo dnf install -y gcc-c++ make tar git

# Node 22
curl -fsSL https://rpm.nodesource.com/setup_22.x | sudo bash -
sudo dnf install -y nodejs
node -v    # 应是 v22.x
npm -v
```

构建：

```bash
cd /opt/mailpost
npm install
npm run build
```

内存不够导致 `Killed` / OOM 时，加 2G 交换分区后再构建：

```bash
sudo dd if=/dev/zero of=/swapfile bs=1M count=2048
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
```

数据目录权限：

```bash
mkdir -p /opt/mailpost/data /opt/mailpost/data/outbox
chmod 700 /opt/mailpost/data
chmod 600 /opt/mailpost/data/mailpost.json   # 若已上传
```

先手动试跑：

```bash
cd /opt/mailpost
npm run start:prod
```

本机浏览器打开 `http://SERVER_IP:5006`，能看到写信页即成功。用 `Ctrl+C` 停掉，改由 systemd 托管。

## 四、用 systemd 常驻（开机自启）

把仓库里的单元文件拷到系统目录：

```bash
sudo cp /opt/mailpost/docs/mailpost.service /etc/systemd/system/mailpost.service
```

若运行用户不是 `ec2-user`（例如 Ubuntu 的 `ubuntu`），编辑该文件里的 `User=`。

```bash
sudo systemctl daemon-reload
sudo systemctl enable mailpost
sudo systemctl start mailpost
sudo systemctl status mailpost
```

常用命令：

```bash
sudo journalctl -u mailpost -f          # 看日志
sudo systemctl restart mailpost         # 重启
sudo systemctl stop mailpost
```

进程应监听 `0.0.0.0:5006`：

```bash
ss -lntp | grep 5006
```

## 五、上线后立刻做的两件事

1. 打开 `http://SERVER_IP:5006/compliance`（设置页）  
   把 **站点（退订链接）** 改成：

   `http://SERVER_IP:5006`

   有域名并做了 HTTPS 则填 `https://你的域名`。不改的话，信里的退订链接仍指向 localhost。

2. **Gmail** 页确认发件箱还在。若没传 `mailpost.json`，在服务器上重新接入 Gmail（应用专用密码）。

测出站 SMTP：

```bash
timeout 5 bash -c 'echo >/dev/tcp/smtp.gmail.com/587' && echo OK || echo FAIL
```

测发信：打开写信页给自己发一封。

## 六、以后如何更新代码

在服务器上（不要覆盖 `data/mailpost.json`）：

```bash
cd /opt/mailpost
# 方式 A：git pull
# 方式 B：本机再 scp 一份 src / package.json 上来

npm install
npm run build
sudo systemctl restart mailpost
```

只改前端/接口代码走上面即可。Gmail 密码、联系人、话术都在 `data/mailpost.json`，更新代码时 **不要删 data 目录**。

备份：

```bash
cp /opt/mailpost/data/mailpost.json /opt/mailpost/data/mailpost.json.bak-$(date +%F)
```

## 七、防火墙（若开了 firewalld）

Amazon Linux 2023 默认常不拦。若 `firewalld` 在跑：

```bash
sudo firewall-cmd --permanent --add-port=5006/tcp
sudo firewall-cmd --reload
```

Ubuntu 用 ufw：

```bash
sudo ufw allow OpenSSH
sudo ufw allow 5006/tcp
sudo ufw enable
```

## 八、故障排查

| 现象 | 处理 |
| --- | --- |
| 浏览器打不开 | 安全组是否放行 5006；`systemctl status mailpost`；`ss -lntp \| grep 5006` 是否 `0.0.0.0:5006` |
| 页面开了但发信失败 Connection closed | 实例访问 `smtp.gmail.com:587` 被拦；检查出站、代理、AWS 邮件限制 |
| Invalid login | 应用专用密码错或已撤销，在 Gmail 页更新 |
| 构建被 Killed | 内存不够，加 swap 或换 t3.small |
| 更新后联系人/邮箱没了 | 覆盖了 `data/mailpost.json`，从备份恢复 |
| 退订链接是 localhost | 设置页改 `publicBaseUrl` 为 `http://SERVER_IP:5006` |

## 九、Ubuntu 22.04 差异

用户一般是 `ubuntu` 不是 `ec2-user`。Node 安装：

```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt-get install -y nodejs
```

systemd 里 `User=ubuntu`，`WorkingDirectory` 仍建议 `/opt/mailpost`。

---

## 十、安全建议（必读）

- 安全组 5006 **只放行你的 IP**，不要对全世界开放。
- `data/mailpost.json` 权限 `600`，不要打进公开镜像或公开 Git。
- 这是内网工具形态。若必须公网访问，前面加 Nginx + HTTPS + 基本认证或 VPN，再把 Node 只绑 `127.0.0.1:5006`。
- Gmail 个人号不适合大规模群发；服务器 IP 信誉也影响进箱。
